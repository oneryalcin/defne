# Visual Concept Prompts

## Purpose

Store reusable image-generation prompts for app concept mockups and future visual direction.

These prompts are not implementation specs. They capture the intended UX feel:

- focused learning time, not social-media engagement
- recurring stylised pencil-drawing avatar
- vocabulary visuals that support retrieval
- parent/child split
- deterministic learning underneath playful presentation
- no real child likeness
- no answer leakage or shame-heavy mistake states

## Prompt 1: Four-Screen Product Overview

Saved concept image: [01-product-overview.png](assets/visual-concepts/01-product-overview.png)

```text
Use case: ui-mockup
Asset type: concept board for a child vocabulary learning web app, preview only
Primary request: Create a polished concept board with 4 distinct app mock screens for a family-pilot vocabulary learning app for a Year 5 girl preparing for English vocabulary practice. The app is pedagogical first, not social-media-like. Show both MVP-1A and later visual-memory stages.

Overall style: warm, focused, premium educational app; calm but playful; pencil-drawing storybook character as a recurring guide; not babyish; not exam-stressful. Use realistic UI mockup fidelity, not wireframe. Avoid social feed, likes, infinite scroll, aggressive rewards, garish neon, or casino-like gamification.

Canvas/layout: one large landscape image containing four labelled mock screens arranged in a 2x2 grid. Keep labels short and readable: “Daily Mission”, “Question + Hint”, “Parent Progress”, “Visual Memory”. Use clean UI text rendered as normal app UI, but keep text minimal and large.

Screen 1: Daily Mission (MVP-1A)
A child dashboard with a small journey map, a recurring stylised pencil-drawing girl avatar, 15-minute mission card, mastery colour strip from red to green with text labels, and today’s focus words. Feeling: inviting, focused, ready to practise.

Screen 2: Question + Hint (MVP-1A / MVP-1B)
A vocabulary question for the word “reluctant” in a sentence context. Show multiple-choice answers, a progressive hint panel, and a small avatar giving a gentle clue. Show mastery dimensions as Meaning, Usage, Spelling with subtle meters. No answer giveaway.

Screen 3: Parent Progress (MVP-1A)
A parent/admin dashboard showing weak words, spelling traps, forgotten-after-delay words, and latest session summary. Dense enough for a parent, calm and readable. Include red/orange/yellow/green status with text labels, not colour alone.

Screen 4: Visual Memory (Later Stage)
A word memory card for “cautious” with the same pencil-drawing girl carefully crossing icy stepping stones. The image supports meaning, while the UI renders the word, definition, spelling chunk “cau + tious”, and a short recall prompt. Show parent-approved visual card state subtly.

Accessibility and UX constraints: do not rely on colour alone; include text labels next to mastery colours. Strong contrast, readable type, clear focus states. No tiny unreadable text. No decorative clutter. Child screen should feel like focused learning time, not entertainment overload.

Visual palette: warm off-white background, ink pencil illustration, forest green, coral/red, amber, sky blue accents, and neutral slate text. Avoid one-note purple or dark blue dominance.

Output: a single cohesive UI concept board, high-quality app mockup, no brand logo, no real child likeness, no copyrighted characters.
```

## Prompt 2: Child Daily Mission Loop

Saved concept image: [02-child-daily-mission-loop.png](assets/visual-concepts/02-child-daily-mission-loop.png)

```text
Use case: ui-mockup
Asset type: child mission flow concept board, preview only
Primary request: Create a polished concept board for a vocabulary learning app focused only on the child’s daily mission loop. Show 3 connected app screens arranged left-to-right: mission start, active practice, end-of-session reflection.

Goal: communicate focused learning time, not a generic quiz and not entertainment overload. The experience should feel like a short personal quest with serious learning underneath.

Style: warm premium educational app, pencil-and-watercolour illustration accents, recurring stylised pencil-drawing girl avatar as a gentle guide, calm but lively. No real child likeness, no brand logo, no social feed, no coins shower, no aggressive gamification.

Screen 1: Mission Start
A compact daily mission card: “Today’s Mission”, 12–15 minutes, a few focus words shown as tiles, mastery status labels red/orange/yellow/green with text labels, and a simple journey path. Avatar stands beside a small notebook/map. UI should make starting feel easy and bounded.

Screen 2: Active Practice
A sentence-context vocabulary task for the word “reluctant”. Show a sentence, four answer choices, a gentle hint button, and visible progress such as “Question 4 of 14”. Include separate tiny meters for Meaning, Usage, Spelling. The interface should show concentration and clarity, not decoration.

Screen 3: Reflection
End screen showing learning movement: “2 words strengthened”, “1 spelling trap found”, “reluctant returns tomorrow”. Include a small path with word tiles moving from red/orange toward yellow/green. Avatar is celebrating quietly with a notebook, not over-the-top.

UX constraints: readable large text, strong contrast, mastery status must include labels not colour alone, no crowded details, clear hierarchy, child can understand what to do next at each step.

Palette: warm off-white, graphite pencil, forest green, amber, coral, sky-blue accents, slate text. Avoid purple-dominant or dark-blue-dominant UI.

Output: single cohesive landscape concept board, realistic high-fidelity app mockup.
```

## Prompt 3: Hint And Mistake Recovery

Saved concept image: [03-hint-mistake-recovery.png](assets/visual-concepts/03-hint-mistake-recovery.png)

```text
Use case: ui-mockup
Asset type: hint and mistake recovery concept board, preview only
Primary request: Create a polished UI concept board for the hardest learning moment in a vocabulary app: the child gets a word wrong, asks for help, and recovers through a hint ladder. Show 4 compact states arranged in a 2x2 grid: first attempt, hint ladder, spelling correction, retry later.

Goal: communicate pedagogical support without shame. The app should diagnose the mistake gently and turn it into the next useful practice step.

Style: focused educational app, warm paper texture, graphite pencil illustration, small recurring stylised girl avatar as a guide. Calm, kind, not childish, not over-celebratory.

State 1: First Attempt
Vocabulary sentence with the word “cautious”. Child selects a tempting wrong answer. UI shows the selected option and a calm “Let’s look closer” feedback state. No red failure alarm.

State 2: Hint Ladder
A progressive hint card with levels: Meaning clue, contrast clue, example clue, spelling clue. Only first two hints visible; later hints locked/collapsed. Avatar points to the context sentence, not the answer. Show that hints are support, not cheating.

State 3: Spelling Correction
A type-from-memory task where the child typed “cautius”. Show a visual correction: cautious, with “cau” and “tious” chunks. Highlight the missing “o” clearly. Include a note: “This is a spelling trap to revisit.”

State 4: Retry Later
A small future-review card: “cautious returns tomorrow”. Show Meaning, Usage, Spelling as separate tracks, with spelling lower than meaning. Include a gentle progress note: “You understood the idea; spelling needs another pass.”

UX constraints: readable text, clear hierarchy, no shame language, no answer giveaway before reveal, no social-media rewards, no colour-only meaning. Include labels with colours. Strong contrast. Minimal decorative clutter.

Palette: off-white, slate text, forest green, amber, coral for warning but not harsh red, pale blue hint accents. Avoid purple dominance.

Output: single landscape UI concept board, high-fidelity mockup.
```

## Prompt 4: Later-Stage Visual Memory And Story

Saved concept image: [04-visual-memory-story.png](assets/visual-concepts/04-visual-memory-story.png)

```text
Use case: ui-mockup
Asset type: later-stage visual memory and story concept board, preview only
Primary request: Create a polished concept board for a later-stage vocabulary app experience where generated visual memory cards are added. Show 3 app screens: word memory card, story map, parent approval.

Goal: communicate how visuals support retrieval, not decoration. The same recurring stylised pencil-drawing girl avatar appears across the scenes, but not as a real child likeness.

Style: elegant illustrated educational app, pencil sketch mixed with soft watercolour, premium storybook learning feel. Calm, purposeful, not cartoonish, not fantasy-heavy, not social-media-like.

Screen 1: Word Memory Card
Word: “reluctant”. Show a visual scene: the recurring girl avatar standing at the edge of a swimming pool, leaning back slightly, unsure about jumping. UI renders the word, short meaning “not willing or hesitant”, a sentence, and recall prompt “Why is she holding back?” Include Meaning / Usage / Spelling progress labels.

Screen 2: Story Map
A journey map with several word locations: cautious bridge, fragile glasshouse, reluctant pool, sincere letter desk. Each location is a memory anchor. Show some locations locked as future review and some completed. The map should feel like structured learning, not a game world that distracts.

Screen 3: Parent Approval
Parent/admin panel reviewing a generated visual card. Show image prompt, status “Draft”, buttons/controls conceptually for approve/reject/regenerate, and a note that text is rendered by app UI, not embedded in image. Include metadata chips: provider, model, prompt version. Dense but readable.

UX constraints: visuals must be tied to word meaning; no image text reliance; clear approved/draft states; readable UI; no public product polish overkill; no real child photos; no copyrighted characters. Use labels with mastery colours, not colour-only.

Palette: paper white, graphite, forest green, amber, coral, soft blue. Avoid purple/dark-blue dominance.

Output: single landscape concept board, high-fidelity UI mockup, visually coherent across the three screens.
```

## Prompt Reuse Notes

- Remove school/year references when they are obvious or not needed.
- Keep the recurring character stylised and fictional, not a real likeness.
- Use visual scenes to encode word meaning, not spelling.
- Render actual words, spelling chunks, and definitions in the app UI, not inside generated images.
- Avoid reward mechanics that pull attention away from learning.
- The four images above were generated as separate text-to-image calls. The later calls did not use the first image as a reference image.
- Character/style consistency came from repeated prompt constraints: recurring stylised pencil-drawing girl avatar, graphite/pencil-and-watercolour style, warm educational UI, and the same palette.
- No explicit seed value was provided or controlled in these generations.
- For stronger production consistency later, use a saved reference image or character sheet as input, or generate a dedicated avatar style guide first and reuse it across prompts.
- When generating production assets later, split these broad concept prompts into narrower prompts per screen or visual card.
